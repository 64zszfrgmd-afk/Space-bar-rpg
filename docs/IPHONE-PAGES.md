# Диагностика запуска и GitHub Pages

Проверено 2026-11-08. Репозиторий: `64zszfrgmd-afk/Space-bar-rpg`.

## Подтверждённые причины недоступности

1. Игра из PR №1 уже объединена в `main` (`a25cd3a`). В workflow [42492783891](https://github.com/64zszfrgmd-afk/Space-bar-rpg/actions/runs/42492783891) сборка и upload успешны, но deploy завершился `Failed to create deployment (status: 404)` с указанием `Ensure GitHub Pages has been enabled`. GitHub Pages нужно включить в настройках репозитория.
2. HTTPS-адрес `https://64zszfrgmd-afk.github.io/Space-bar-rpg/` возвращает 404. Это подтверждённая проблема публикации, а не доказанная неисправность конкретного iPhone.
3. Обычная исходная сборка создаёт `/assets/index-….js` и `/assets/index-….css`. На project Pages эти адреса указывают на корень домена, а игра размещается в `/Space-bar-rpg/`. В прежнем workflow путь исправлялся только параметром команды; локальная сборка и публикация отличались.
4. Исходный HTML зависел от успешной загрузки JS и не имел сообщения об ошибке загрузки модуля. При отказе JS пользователь мог видеть пустой экран.
5. Предыдущая Cloud-среда и временные адреса Vite недоступны. `localhost` и ZIP-предпросмотр iPhone не являются постоянным хостингом игры.

## Расхождение версии и блокеры публикации

В `main` и `work` версия пакета — **0.1.0**, четыре NPC, без Боркса, каюты и прочего контента ранее созданной **0.20**. Ветка `fix/iphone-pages-launch` в PR №2 исправляет публикацию этого доступного проекта. Архив `spacebar_web_0_20.zip` отсутствует в новой рабочей среде. Нельзя утверждать, что эти другие исходники являются 0.20, или подтвердить исправление отсутствующей сборки. Запрошена ссылка на исходники 0.20. Игровые функции 0.30 не разрабатываются.

Pages API отвечает **403 Resource not accessible by integration**: подключение GitHub не имеет доступа к настройкам Pages. Репозиторий приватный; доступность Pages также зависит от тарифа владельца. Видимость репозитория и тариф не менялись. PR №2 не объединяется автоматически. Эти ограничения не мешают подготовить исправления и проверить их в PR.

## Изменения

- Добавлен единый `base: '/Space-bar-rpg/'` в `vite.config.ts`, целевая сборка JavaScript для Safari 15.4+.
- Three.js остаётся локальной npm-зависимостью и включается в JS-бандл. Внешний CDN для запуска не нужен.
- Добавлен независимый загрузочный экран с повторной загрузкой и сообщениями о недоступном скрипте, WebGL 2, долгом запуске и потере 3D-контекста. Экран скрывается после первого отрисованного кадра.
- Для сенсорных экранов отключён MSAA и ограничен pixel ratio до 1.25, чтобы сократить расход памяти рендера. Измерений FPS на устройствах нет.
- Дополнены safe areas, `dvh` с `vh` fallback, поведение прокрутки, размер кнопок, альбомный интерфейс и префикс backdrop-filter для Safari. Закрытие диалога не прокручивает страницу; выход со страницы сохраняет состояние и сбрасывает ввод.
- Actions проверяет PR, собирает и тестирует проект, загружает отчёты и `dist`. Production deploy выполняется только из `main`; отдельное задание использует Pages/OIDC-права и официальный deployment action.
- Добавлены проверки правильного project path и MIME ресурсов через строгий статический сервер, а также Chromium/WebKit-сценарии запуска и ошибок.

## Фактические проверки

- Исходная `npm ci` и TypeScript/Vite-сборка пройдены, исходные `/assets/…` воспроизведены в `dist/index.html`.
- После исправления `npm test`: сборка и три проверки production path, HTTP/MIME и trailing slash пройдены.
- Chromium с эмуляцией 390×844 и 844×390: 3D-кадр, JS/CSS из подпапки, кнопки, отсутствие прокрутки и сообщения при отказе скрипта/WebGL пройдены. Нет ошибок браузера и внешних запросов в успешном запуске.
- Локальный WebKit скачан, но в новой среде отсутствуют GTK4, Graphene, HarfBuzz ICU, Manette, Hyphen и GLES-библиотеки. Его локальный запуск не считается пройденным. В CI установка зависимостей и запуск обоих движков обязательны; результат будет указан в PR после фактического выполнения.
- Физический Safari на iPhone не проверен. Публичная HTTPS-публикация 0.20 не подтверждена: нужных исходников и доступа к Pages settings пока нет.

## Что сделать на GitHub с iPhone

1. Восстановить исходники 0.20 в ветке подготовленного PR и повторить проверки на них. Не переименовывать версию 0.1.0 для обхода этого шага.
2. В PR №2 проверить вкладку **Checks**, затем **Ready for review → Merge pull request → Confirm merge**. PR №1 уже объединён, повторять его не нужно.
3. В **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**. Если приватный репозиторий недоступен для Pages на текущем тарифе, решить вопрос тарифа или видимости отдельно.
4. В **Actions → Test and deploy GitHub Pages** дождаться успешных `build` и `deploy`. При необходимости **Run workflow → main**. Если environment требует одобрения, подтвердить deployment владельцем.
5. Открыть адрес из успешного задания deployment в Safari: ожидаемый `https://64zszfrgmd-afk.github.io/Space-bar-rpg/`. Пока `deploy` не прошёл, считать ссылку рабочей нельзя.

Постоянной является ссылка Pages после успешной публикации, а не адрес предпросмотра Cloud. Никакие новые игровые версии не нужны для включения хостинга.
