## Что переносить после получения исходников

1. Получить исходное дерево: Git bundle/репозиторий с `a8b5510` либо оригинальный архив `spacebar_web_0_20.zip`. Проверить `package.json` с `0.20.0`, модули и отчёт этапа. Архив без Git-объектов позволяет проверить содержимое, но сам по себе не доказывает происхождение от конкретного SHA.
2. В отдельной ветке импортировать существующие модули 0.20: `src/engine`, `player`, `world`, `interactions`, `npc`, `ui`, `storage`, `game`, `legacy`, `scripts/prepare-legacy.mjs` и их тесты. Сначала сохранить исходный lock-файл и совместимые зависимости; не пересоздавать игровые механики.
3. Сохранить из текущего main GitHub Pages base path `/Space-bar-rpg/`, Actions/OIDC, HTTPS-запуск, независимый загрузочный экран и сигнал готовности после первого кадра, сообщения об отказе WebGL, safe areas и ограничение мобильной нагрузки. Подключить их к существующему renderer/loop 0.20; не создавать второй renderer и второй цикл.
4. Не терять работающие возможности опубликованной игры: четыре существующих NPC и их диалоги, четыре напитка с прежними ценами/эффектами, бесплатную воду, управление, камеры, музыку и сохранения. Бип и Боркс, Зора и Зип — разные персонажи; автоматически объединять их идентичности нельзя. При добавлении их в восстановленный мир нужны отдельные стабильные ID и проверка доступности.
5. Добавить однократную миграцию данных `spacebar-v1`: credits → money, buzz → drunk, mood → vitals.mood, энергия по умолчанию. Сохранить исходный ключ до проверки результата. Существующий валидный `spacebar-save-v2` имеет приоритет и не должен перезаписываться старым или пустым сохранением. Имена знакомств сопоставлять только с соответствующими NPC; неизвестные записи сохранять, а не удалять.
6. Сохранить привычную клавишу T как совместимый вызов танца наряду с F/Пробелом 0.20. При изменении UI проверить прежние возможности через реальные кнопки и касания.
7. Учесть автономный HTML 0.20: прежний `vite-plugin-singlefile` может не создавать внешние JS/CSS. Проверки публикации должны корректно проверять как inline-сборку, так и внешние локальные ресурсы. Не удалять автономную сборку ради теста, требующего внешние файлы.
8. Запустить исходные 24 unit-теста и сценарии 0.20 для взаимодействий, заведений, рейсов, фестиваля, каюты; добавить проверку сохранений из опубликованной 0.1.0. Повторить TypeScript/Vite, Chromium/WebKit, portrait/landscape, отсутствие внешних запросов, посадку, оплату и награды без повторных списаний.
9. Только после восстановления и проверок снять Draft, объединить PR, дождаться production deployment и подтвердить совпадение опубликованной сборки с восстановленным исходником. Номер `0.20.0` устанавливать по реальному коду, а не для смены подписи сайта.

Автоматическая миграция localStorage возможна только в том же браузере и origin. Сохранение из старого Cloud-адреса не становится доступным домену GitHub Pages само по себе; для такого случая нужен экспорт/импорт сохранённой копии. Наличие исходного архива игры не означает наличие браузерного сохранения.

## Проверки текущего этапа

- На текущем main повторно пройдены `npm ci`, TypeScript/Vite build и 3 проверки production URL/MIME.
- `npm run audit:published` сравнивает HTML/JS/CSS сайта с текущей локальной сборкой; результат — `test-results/published-version-audit.json`. Нужны Git и curl, TLS-проверка не отключается. При отличии байтов команда завершается ошибкой и не приписывает сайту версию checkout.
- Браузерный сценарий теперь принимает `SPACEBAR_TEST_URL=https://64zszfrgmd-afk.github.io/Space-bar-rpg/`. Проверки live сохраняются отдельно в `test-results/published/`.
- Прямой браузерный запрос из Cloud встретил ошибку доверия к сертификату прокси (`ERR_CERT_AUTHORITY_INVALID`); проверка TLS не отключалась. Это не доказательство дефекта сертификата сайта на iPhone. Для реального HTTPS запускается отдельный CI в обычном GitHub runner с Chromium и WebKit.
- Физический iPhone не тестировался. Тесты отсутствующего дерева 0.20 повторно не запускались и не объявляются пройденными.

**Статус переноса: заблокирован отсутствующим исходным деревом 0.20.** Этот PR готовит проверяемое сравнение и безопасный перенос, но не публикует восстановленную 0.20. Новых игровых функций и версии 0.30 здесь нет.
