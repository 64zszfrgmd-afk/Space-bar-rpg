# Резервная точка и откат production 0.21.3

Подготовка сама ничего не публикует в Pages. Снимок включает root 0.21.0 и тестовые 0.21.1/0.21.2/0.21.3: все 233 файла закреплены SHA-256 в `hosting/production-before-0213.json`.

Постоянная Git-точка исходников: ветка `backup/production-0.21.0-before-0.21.3` на `ffa62be7404559a51157a86efbc3785b7dece82a`. В репозитории уже хранится `hosting/production-0.21.0.tar.gz`: исходный опубликованный root, SHA-256 `d31e1a799199240d2f9700eb141e5a8d207a746967abb7590162b54215f80128`, автоматически сверяемый с 6 файлами.

CI сохраняет полный статический сайт в **draft recovery release** `production-backup-0.21.0-20261114-ffa62be`: `published-before-0213.tar.gz`, его `.sha256` и JSON всех 233 хешей. Это резервная копия, не релиз новой игры и не изменение Pages. Архив детерминированный; существующие данные не перезаписываются. Повторная CI-проверка сверяет исходный checksum и содержимое. Дополнительно оба пакета `production-candidate` и `published-backup-before-0213` хранятся 90 дней в Actions. Draft release доступен владельцу в Releases; для восстановления после истечения Actions использовать его. Gate `permanent recovery point` обязан пройти до merge/deploy.

## При проблеме после разрешённого production-deploy

1. Сохранить отчёт проблемы, production run/SHA и экспорт прогресса через меню. Откат файлов **не очищает localStorage**, не меняет origin/ключ и не подменяет сохранение тестовым. Не нажимать «новая игра», не очищать данные Safari.
2. По отдельному разрешению владельца запустить Actions → **Restore published production snapshot** → Run workflow → `confirmation=RESTORE-0.21.0` на коммите подготовленного релиза. Сейчас этот workflow **не запускается**.
3. Workflow проверяет SHA архива, восстанавливает каждый из 233 закреплённых файлов. При доступном production manifest сохраняет также новые хешированные assets для кешированных страниц 0.21.3. Старые тестовые версии остаются неизменными. Публикация использует ту же очередь `github-pages-production` и environment `github-pages`.
4. Автоматически проверяются HTTPS-хеши всего восстановленного пакета. Проверить на iPhone root 0.21.0 и прежний прогресс. 0.21.0 может снова иметь прежние визуальные ограничения моделей; это причина отката к известной основной версии, а не новое исправление.
5. Статический откат не меняет main. Для следующих деплоев подготовить отдельный revert PR и запросить разрешение. Автоматический production workflow намеренно откажется публиковать поверх изменившегося baseline: сначала снять и проверить новый снимок.

Совместимость данных проверяется в браузере: новая 0.21.3 сохраняет прогресс, затем **те же origin, путь и localStorage** загружают архивный 0.21.0, сохраняют его без потери имени/вида, кредитов, места, квестов, отношений, инвентаря, посещений и решений; повторная 0.21.3 снова загружает эти данные. Не требуется восстанавливать старую резервную копию поверх нового прогресса. Игровая миграция сохраняет схему 2, основной ключ `spacebar-restored-v020`, legacy `spacebar-v1`; существующая резервная копия остаётся нетронутой.

Если GitHub Releases временно недоступен, доступен Actions backup в пределах retention. В крайнем случае root можно получить из постоянного Git-архива, а тестовые файлы — из проверенного полного backup; **нельзя** загружать только root-архив как полный Pages artifact: это удалит `/test/`.
