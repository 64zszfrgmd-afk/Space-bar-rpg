# 0.21.1 — диагностика полного пути на телефоне

Работа продолжается в `feature/v0.21-world-fixes`, поверх main `ffa62be` (PR №6 уже объединён владельцем). Новый код не объединяется и не публикуется в main. Объединённый PR нельзя переоткрыть или дополнить новыми коммитами: в его описание добавляется ссылка на исправление и отдельный draft PR с той же ветки.

## Что установлено и что остаётся неизвестным

Прежнее объяснение только камерой не объяснило результат физического iPhone. Без отчёта с этого устройства нельзя установить его точную причину. В 0.21.0 воспроизведены отдельные программные дефекты полного пути:

- Новое прохождение: восемь маршрутов — нативные disabled-кнопки. Касание не вызывает проверку или сообщение об отказе.
- Пропуск найден, story=5: те же восемь кнопок отключены. Предъявить пропуск прямо из карты нельзя; без использования физического выхода мир остаётся закрытым.
- Старое сохранение с `docks:open`/историей посещений, но потерянным номером этапа: загрузка возвращает в исходный бар и закрывает все маршруты, хотя данные доказывают, что доступ уже был.
- Обработчик выбора сначала отключал кнопку и не включал её обратно, если действие отказало или завершилось исключением без замены окна.
- У длинных окон на телефоне не было постоянной кнопки закрытия; пользователю приходилось искать выход внизу списка. На компактном альбомном экране зоны игровых кнопок могли пересекаться.

Исходные воспроизведения: [результаты](touch-0211-baseline/results.json), [пропуск есть, маршруты отключены](touch-0211-baseline/pass-not-validated.png). Это браузерная проверка исходной 0.21.0, не журнал пользователя с физического iPhone.

## Исправления

1. Каждое касание маршрута теперь проходит настоящую проверку доступа. Закрытый маршрут остаётся нажимаемым и объясняет `PASS_MISSING` или `DOCKS_NOT_VALIDATED`. Бесплатный сюжет не пропускается: карта предлагает найти нужного NPC, а найденный пропуск можно предъявить прямо здесь. Награда завершения выдаётся один раз.
2. Сохранённые признаки ранее открытых доков/посещённых миров согласуются с этапом сюжета и пропуском. Валюта, задания и отношения сохраняются, повторных наград нет. Сырые данные прежнего сохранения перед первым обновлением копируются в `spacebar-restored-v020-backup-before-0211`; старый ключ и prototype-save не удаляются.
3. Повторяемые/отклонённые действия не оставляют кнопку заблокированной. Ошибки обработчика показываются в игре. Окно имеет постоянное закрытие, отдельный прокручиваемый список и определённую высоту для Safari. Панель диагностики не принимает касаний; модальные элементы выше игрового HUD, а области кнопок на компактном экране разделены.
4. Жителя можно выбрать и подойти к нему из игрового меню. Герой идёт обычным движением по свободным проходам с коллизиями; это не телепортация и не удалённый разговор. Ручное движение/обзор отменяет подход. Выбранный NPC имеет приоритет над соседним стулом. Касание видимой модели/подписи также выбирает NPC; учитывается перекрытие окружением. Сброс ввода отменяет незавершённое касание.
5. Постоянная временная панель показывает версию 0.21.1, текущую/отрисованную локацию, пропуск, доки и последний результат. Меню → «Диагностика и копирование отчёта» включает адрес, build ID, источник сохранения, изменения при загрузке, pointerdown/click последнего маршрута, этапы перехода, выбранного NPC и ошибку. Меню → «Резервная копия прогресса» позволяет сохранить JSON без очистки браузера.

## Что проверяется полностью через production UI

`tests/user-journey.mjs` **не включает DEV-интерфейс**, не меняет координаты модели и не выставляет story=6 для нового прохождения.

- Новое прохождение: настоящее касание закрытого маршрута → сообщение об отказе → подход к Борксу, Зипу, Лире и Мире-7 через игровое меню → настоящие ответы в диалогах → получение пропуска → отказ до предъявления → предъявление на карте → девять путешествий и управление после каждого.
- Все 23 NPC: выбор жителя в меню → видимое обычное движение героя по проходу → касание кнопки взаимодействия → проверка имени открытого диалога. Снимки и позиции записываются. Переноса игрока тестовым кодом нет.
- Репрезентативные сохранения 0.20 R2 и 0.21 с противоречивыми/неполными признаками доступа: восстановление доков, все девять маршрутов, сохранность кредитов/заданий, перезагрузка, резервная копия.
- Для каждого нажатия проверяется `elementFromPoint` и высота цели не менее 44 px. Используются нативные touch taps, включая карту и диалоги. Chromium дополнительно использует удержание джойстика через CDP touch; WebKit — touch tap и удержание pointer на touch viewport. Это не проверка физического multi-touch на iPhone.
- Компактный альбом: карта → переход → подход к Борксу → реальный диалог → закрытие пальцем. Старые сценарии продолжают проверять десять заданий, экономику, напитки, сиденья, камеры, ритм и модели.

Итоговые данные и PNG: `test-results/user-journey/`; они включены в отдельный архив визуального отчёта вместе с предыдущей матрицей 9 сцен / 23 NPC / 5 героев. Результат каждого движка указывается в PR после выполнения, а не заранее.

## Повторная проверка на iPhone

Открой новый HTTPS-предпросмотр порта **5173**, путь `/Space-bar-rpg/?build=0.21.1`. Сверху должна постоянно отображаться **0.21.1**. GitHub Pages остаётся на main 0.21.0; этот адрес не получает исправление без отдельного подтверждения публикации. Сохранения привязаны к адресу: данные Pages не становятся данными Cloud-предпросмотра автоматически.

После неудачного действия открой меню → «Диагностика и копирование отчёта» и скопируй текст. Если pointerdown есть, а click отсутствует — проблема доставки касания; если `PASS_MISSING`/`DOCKS_NOT_VALIDATED` — показано конкретное условие; `LOCATION_FAILED` означает отказ построения/рендера; `CONTROLS_READY` с неизменившимся изображением требует анализа устройства/кадра. Не нужно очищать localStorage для обновления: в нём находится прогресс.

Без этого физического отчёта остаётся неизвестным, совпадает ли найденная ошибка с причиной конкретного iPhone. Сборка предназначена для повторного тестирования, а не объявляется доказанным исправлением всех аппаратных случаев.
